TCG Pocket: worker 0.2.11 en Android arm64 (T-015)

1. Instalá Termux desde F-Droid o los releases oficiales de GitHub, no desde Play Store.
   Termux:API, Termux:Boot y Termux:Widget deben venir del MISMO origen: las firmas de los APK son distintas.
   https://github.com/termux/termux-app#installation
2. En la app, Más → Tokens de API: creá un token de tipo worker exclusivo para el celu.
   Copiá el comando de «Worker en Android» y pegalo en Termux.
   El instalador pide el token oculto dentro de Termux. No lo pongas en el comando ni en la URL.
   Guarda la config con permisos 600. La descarga requiere HTTPS y Authorization: Bearer;
   comprueba la suma SHA256 antes de instalar. Node se instala con pkg install nodejs-lts.
   Paquete oficial consultado el 10/10/2026: Node 24.18.0. Se requiere Node >=24.
   https://github.com/termux/termux-packages/blob/master/packages/nodejs-lts/build.sh
3. Elegí cuántos núcleos usar (por defecto la mitad, por el calor) y si trabaja solo enchufado.
   «Nombre en la app» permite identificar tu celu. Enter conserva el nombre guardado;
   la primera vez propone «Android», también si el nombre viejo era «Android localhost».
   El motor de fondo usa prioridad baja para dejar CPU a otras tareas. La prioridad no reduce el calor.
   Para esa opción instalá Termux:API y pkg install termux-api. Se revisa cada 15 segundos;
   una lectura de batería fallida pausa el trabajo. Desenchufar manda SIGTERM, libera los
   leases sin contar fallas y al enchufar se reanudan los resultados pendientes.
4. tcg-worker arranca, pide termux-wake-lock y lo libera al salir. Ctrl+C o tcg-worker --stop lo detienen.
   --stop verifica el PID de nuestros locks, manda SIGTERM y espera la limpieza de leases.
   Si no corre ninguno, lo dice. Si el PID es de otro proceso, no lo mata y avisa.
   tcg-worker --check prueba determinismo, configuración y servidor sin reclamar trabajo.
   Si ARM no reproduce la referencia de la PC, se detiene y explica la diferencia.
   La prueba es corta: no demuestra que todas las partidas posibles sean idénticas.
   Los cortes de red no reinician una simulación en curso: el worker sigue intentando
   renovar el lease cada 30 s. Si otro worker tomó el chunk, corta el motor y sigue.
   Las partidas contra el bot reintentan los cortes sin llenar el log de timeouts.
   worker.log muestra el código y la señal de salida de cada motor; si termina sin
   resultado, informa la falla del chunk y continúa con el siguiente.
5. Arranque opcional: instalá Termux:Boot y abrilo una vez antes de reiniciar el celu.
   El instalador escribe ~/.termux/boot/tcg-worker solo si lo elegís.
6. Para actualizar, repetí el mismo comando. Detiene el worker, instala motor y JS juntos,
   conserva el id del worker y resultados pendientes, pide nuevamente las preferencias.
   Solo trabaja con la versión del motor que corresponde a la imagen de la API.
7. Para manejarlo con un toque: instalá Termux:Widget desde F-Droid (si Termux vino de ahí)
   y respondé «s» a «¿Accesos directos para Termux:Widget?» en el instalador.
   Mantené presionado un espacio vacío de la pantalla de inicio → Widgets → Termux:Widget;
   arrastrá el widget y tocá su botón de refrescar. Los nombres son:
   - Arrancar worker: abre una sesión con el wake-lock del lanzador; si ya corre, avisa.
   - Detener worker: corre sin ventana, espera el apagado y muestra un termux-toast
     si está instalado pkg install termux-api y la app Termux:API responde.
   - Estado del worker: comprueba motor y conexión, y espera Enter para cerrar la sesión.
   Al reinstalar se actualizan; con «n» se borran esos tres scripts. Refrescá el widget.
   El instalador usa ~/.shortcuts/ y ~/.shortcuts/tasks/ (Detener), con permisos 700
   y shebang absoluto de Termux. Otros accesos que tengas se conservan.

Permisos del widget (también Android 12+):
La documentación oficial pide opcionalmente «Mostrar sobre otras apps» a TERMUX,
no a Termux:Widget, desde Android 10 para abrir las sesiones desde segundo plano:
Ajustes → Apps → Termux → Acceso especial / Mostrar sobre otras apps → Permitir.
Si no lo concedés y la sesión no aparece, tocá la notificación de Termux para abrirla.
Detener worker no necesita abrir una sesión. Widget no declara permisos adicionales
en su manifiesto; no necesita acceso al almacenamiento compartido para estos scripts.
Fuentes oficiales verificadas el 10/10/2026:
https://github.com/termux/termux-widget#setup-instructions
https://github.com/termux/termux-widget#draw-over-apps-permission-optional
https://github.com/termux/termux-widget/blob/master/app/src/main/AndroidManifest.xml

Prioridad:
En data/config.json: "priority": "below_normal" (por defecto), "normal" o "idle".
TCG_WORKER_PRIORITY manda sobre el archivo. --check muestra el valor. Si Android rechaza cambiar
la prioridad, se registra en worker.log y sigue con la heredada. Las partidas contra el bot y las
pistas del entrenador mantienen prioridad normal; los latidos del worker conservan su prioridad.

Batería y calor:
Android → Apps → Termux → Batería: elegí «Sin restricciones» / excluir optimización;
permití también Termux:API y el arranque automático que ofrezca el fabricante.
Simular consume batería y calienta, incluso mientras carga. Empezá con pocos núcleos,
dejá ventilación y frenalo si calienta demasiado. El wake-lock evita dormir la CPU y consume
energía; «solo mientras carga» mantiene el supervisor despierto para detectar el enchufe.
Android puede matar Termux por memoria o políticas del fabricante: el trabajo vuelve a la
cola al vencer el lease (3 minutos si no se pudo liberar al salir). SIGKILL no permite cleanup.

Phantom process killer (documentación consultada el 10/10/2026):
Android 14+: Opciones de desarrollador → «Disable child process restrictions» /
«Desactivar restricciones de procesos secundarios», y mantené las opciones activadas.
Android 12L/13 y superiores, desde una PC con adb autorizado:
  adb shell settings put global settings_enable_monitor_phantom_procs false
Verificar: adb shell settings get global settings_enable_monitor_phantom_procs
Deshacer: adb shell settings delete global settings_enable_monitor_phantom_procs
Android 12 original: no tiene esa opción para CPU excesiva. Para el límite de procesos:
  adb shell device_config set_sync_disabled_for_tests persistent
  adb shell device_config put activity_manager max_phantom_processes 2147483647
Deshacer: adb shell device_config delete activity_manager max_phantom_processes
  adb shell device_config set_sync_disabled_for_tests none
Esto afecta la política de procesos del dispositivo; el instalador NO cambia esos ajustes.
Guía de un mantenedor de Termux, con las diferencias por versión y fabricante:
https://github.com/agnostic-apollo/Android-Docs/blob/master/en/docs/apps/processes/phantom-cached-and-empty-processes.md
