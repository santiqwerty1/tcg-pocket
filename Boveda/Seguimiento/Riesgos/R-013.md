# R-013 — Commits con el mail personal como autor en el repo público

<!-- estados: abierto · resuelto · descartado · por_revalidar -->

## Riesgo

La mudanza ([D-022](../Decisiones/D-022.md)) reescribió toda la historia con el autor noreply, pero el `user.email` local del repo siguió siendo el mail personal. Desde la mudanza, 37 de los 56 commits de main (de `abd5034` a `b0c3627`) llevan ese mail como autor en el repo público. Los merges de GitHub usan el noreply. Cada commit nuevo hecho con esa configuración lo vuelve a publicar.

## Mitigación

- **12/10/2026, el Coordinador** puso el noreply en la configuración local del repo, que comparten todos los worktrees. También avisó a las sesiones que reescriban el autor de sus commits sin subir.
- **Regla en `CLAUDE.md`** («Cómo trabajar acá», repo público): antes de cada push, `git log --format='%h %ae %ce' origin/main..HEAD` tiene que mostrar solo el noreply.
- **Lo ya publicado queda como está.** Santiago decidió el 12/10/2026 corregir solo hacia adelante y no reescribir main.

## Seguimiento

- 12/10/2026: verificado con `git log abd5034..origin/main --format='%ae'`: 56 commits, 37 sin noreply. La actualización de la bóveda del 12/10 ya se hizo con el noreply.
- **Pendiente para Santiago** (recomendación del Coordinador): activar en su cuenta de GitHub «Keep my email addresses private» y «Block command line pushes that expose my email». Con eso, GitHub rechaza un push que vuelva a exponerlo. Cuando esté activado, el riesgo se puede dar por resuelto.
